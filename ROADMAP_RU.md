# Дорожная карта: tiny-qwen → Go

Точный порт [Emericen/tiny-qwen](https://github.com/Emericen/tiny-qwen) (Python/PyTorch) на чистый Go, без внешних зависимостей. Этапы упорядочены так, чтобы после каждого оставался работающий результат.

## Этап 0 — Основы ✅ (готово, коммит f601173)
- [x] `safetensors` — читатель формата HF safetensors: F32/F16/BF16/I8/U8 → float32, сырой доступ к байтам для квантованных тензоров
- [x] `tokenizer` — байтовый BPE из `tokenizer.json`, собственная реализация пре-токенизатора Qwen2 (в Go regexp нет lookahead'ов), encode/decode/специальные токены

## Этап 1 — Текстовое ядро, плотная модель 🚧 (следующий)
Цель: жадная генерация со стримингом для плотной модели семейства Qwen3 из локальной директории с чекпоинтом.
- [ ] `model/config.go` — разбор `config.json` (плоский и вложенный `text_config`)
- [ ] загрузка и переименование весов (`model.` → ничего, tie embeddings), проверка state dict
- [ ] нормы: RMSNorm и GemmaRMSNorm (вариант `1+w`)
- [ ] частичные ротари-эмбеддинги, внимание GQA с per-head нормами q/k и выходным гейтом q
- [ ] KV-кэш (добавление + чтение по смещению)
- [ ] плотный MLP SwiGLU, связанная lm head
- [ ] жадная генерация со стримингом (argmax, как `temperature=0` в Python-версии)
- [ ] `cmd/tiny-qwen` — минимальный чат-REPL с шаблоном `im_start/im_end` и переключателем режима размышления
- [ ] валидация: эталонные логиты от Python-версии на маленьких случайных весах; смоук-тест на Qwen3-0.6B

## Этап 2 — MoE + квантизация
- [ ] роутер MoE (softmax по экспертам, top-k), батчированные экспертные MLP (3D-веса), общий эксперт
- [ ] `QuantLinear` int8/int4: групповая деквантизация прямо в matmul (формат: fp16-скейлы + упакованные uint8-веса)
- [ ] режим `--bits 4`: чтение F32/BF16-чекпоинта, запись квантованной директории (Go-версия `quantize_model`)
- [ ] валидация: квантованный чекпоинт Python против Go, токен за токеном

## Этап 3 — GatedDeltaNet + модели со смешанными слоями
Цель: запуск всего текущего поколения архитектур с `main` (Qwen3.5–3.8).
- [ ] слой GDN: каузальная depthwise conv1d, l2-норма, рекуррентность gated delta rule, гейтирование ключей/значений, низкоранговые Q/K с гейтами a/b и dt bias
- [ ] диспетчеризация слоёв по `layer_types` (`SelfAttention` против `GatedDeltaNet`)
- [ ] кэширование состояния GDN (рекуррентное состояние вместо KV)
- [ ] валидация: поклейочный тест одного слоя против Python для обоих типов миксеров

## Этап 4 — Зрение
- [ ] декодирование изображений через стандартную библиотеку Go (`image/jpeg`, `image/png` — без зависимостей), бикубическое изменение размера, нормализация
- [ ] динамическое разрешение (бюджет min/max пикселей), нарезка патчей 16px с упорядочиванием 2×2-слияния
- [ ] башня ViT: patch embedding, mRoPE (2D), блоки full-attention, pixel-merge → токены языковой модели
- [ ] мультимодальный процессор: вставка `<|vision_start|>...<|vision_end|>`, позиционные id mRoPE из трёх секций
- [ ] валидация: в оригинальном репозитории есть фикстуры `test/data/qwen35_transformers_mm_outputs.json` — переносим эти тесты

## Этап 5 — Паритет обвязки
- [ ] полный агентный REPL из `run.py`: разбор/рендеринг вызовов инструментов, системные промпты, история чата
- [ ] режим проксирования на OpenAI-совместимый API (`--url/--api-key/--model`, Go `net/http`)
- [ ] CLI-флаги как в Python (`run.py Qwen/Qwen3.8-27B --bits 4 ...`)

## Этап 6 — Производительность (только если это кого-то беспокоит)
- [ ] нативный matmul в bf16 (без апкаста), mmap-веса
- [ ] параллельный matmul через горутины, дружелюбный к кэшу расклад памяти
- [ ] опциональные ускорения префилла на одном батче (декод в чистом Go — ок для маленькой реализации)

## Явные не-цели (как и в оригинале)
Обучение, батчинг/обслуживание многих пользователей, GPU-ускорение. Это читаемая эталонная реализация.

## Стратегия валидации
Каждый этап сверяется с Python-реализацией: фиксированные входы → логиты/argmax-токены, где есть — готовые фикстуры. Порт, который «выглядит правильно», не считается готовым.
